# Sistema de Migração e Sincronização de Dados

## 📋 Visão Geral

Este documento descreve o sistema completo de migração e sincronização de dados implementado no Louve Mobile App. O sistema garante que os dados do usuário sejam preservados e sincronizados entre dispositivos, mesmo quando o usuário faz login pela primeira vez ou troca de dispositivo.

## 🎯 Problemas Resolvidos

### ❌ **Antes da Implementação:**
1. **Perda de dados locais**: Usuários perdiam favoritos e configurações ao fazer login
2. **Sem sincronização**: Dados não eram sincronizados entre dispositivos
3. **Conflitos não resolvidos**: Não havia estratégia para resolver conflitos de dados
4. **Sincronização manual**: Usuários precisavam fazer logout/login para sincronizar

### ✅ **Após a Implementação:**
1. **Migração automática**: Dados locais são migrados automaticamente após login
2. **Sincronização em tempo real**: Dados são sincronizados automaticamente
3. **Resolução de conflitos**: Conflitos são detectados e resolvidos automaticamente
4. **Sincronização automática**: Sistema monitora conectividade e sincroniza quando necessário

## 🏗️ Arquitetura do Sistema

### **Componentes Principais:**

#### 1. **DataMigrationService**
- **Responsabilidade**: Migra dados locais para a nuvem após login
- **Funcionalidades**:
  - Backup de dados locais antes da migração
  - Merge inteligente de favoritos e configurações
  - Limpeza de dados locais após migração bem-sucedida
  - Tratamento de erros e logging detalhado

#### 2. **BidirectionalSyncService**
- **Responsabilidade**: Sincronização bidirecional entre dados locais e remotos
- **Funcionalidades**:
  - Sincronização remoto → local
  - Detecção de conflitos
  - Resolução automática de conflitos
  - Merge inteligente de dados

#### 3. **ConnectivityMonitorService**
- **Responsabilidade**: Monitora conectividade e automatiza sincronização
- **Funcionalidades**:
  - Monitoramento de mudanças de conectividade
  - Sincronização automática quando conectividade é restaurada
  - Sincronização forçada manual
  - Tratamento de erros de rede

#### 4. **Repositórios Atualizados**
- **DefaultFavoritesRepository**: Integrado com serviços de sincronização
- **DefaultSettingsRepository**: Integrado com serviços de sincronização
- **FirestoreUserRepositoryImpl**: Executa migração após criação de estrutura

## 🔄 Fluxo de Funcionamento

### **1. Login do Usuário**
```
1. Usuário faz login com Google
2. FirebaseAuthRepositoryImpl cria perfil no Firestore
3. FirestoreUserRepositoryImpl.ensureUserStructure() é chamado
4. Estrutura do usuário é criada/verificada
5. DataMigrationService.migrateLocalDataToCloud() é executado em background
6. Dados locais são migrados para a nuvem
7. Dados locais são limpos após migração bem-sucedida
```

### **2. Migração de Dados**
```
1. Backup dos dados locais (favoritos + tema)
2. Obtenção dos dados existentes na nuvem
3. Aplicação de estratégia de merge:
   - Favoritos: União de dados locais e remotos
   - Tema: Preferir tema local se for personalizado
4. Salvamento dos dados mesclados na nuvem
5. Limpeza dos dados locais
```

### **3. Sincronização Automática**
```
1. ConnectivityMonitorService monitora conectividade
2. Quando conectividade é perdida: Modo offline ativado
3. Quando conectividade é restaurada:
   - Verifica se usuário está logado
   - Executa sincronização remoto → local
   - Detecta e resolve conflitos se necessário
   - Atualiza dados locais
```

### **4. Resolução de Conflitos**
```
1. Detecção de diferenças entre dados locais e remotos
2. Backup dos dados locais
3. Aplicação de estratégia de merge inteligente
4. Salvamento dos dados mesclados na nuvem
5. Atualização dos dados locais
6. Logging detalhado do processo
```

## 🎯 Estratégias de Merge

### **Favoritos**
```kotlin
private fun mergeFavorites(local: Set<String>, remote: Set<String>): Set<String> {
    return when {
        local.isEmpty() -> remote           // Só dados remotos
        remote.isEmpty() -> local           // Só dados locais
        else -> local.union(remote)        // União de ambos
    }
}
```

### **Tema**
```kotlin
private fun mergeTheme(local: String, remote: String): String {
    return when {
        local == DefaultTheme.name -> remote    // Preferir tema remoto se local for padrão
        remote == DefaultTheme.name -> local   // Preferir tema local se remoto for padrão
        local != remote -> local               // Em caso de conflito, preferir tema local
        else -> local                          // Mesmo tema, usar local
    }
}
```

## 📱 Casos de Uso

### **Cenário 1: Usuário Novo Faz Login**
```
1. Usuário instala o app e marca 3 hinos como favoritos
2. Usuário escolhe tema "dark"
3. Usuário faz login com Google
4. Sistema detecta dados locais
5. Dados são migrados para a nuvem
6. Usuário pode acessar favoritos e tema em qualquer dispositivo
```

### **Cenário 2: Usuário Existente Faz Login em Novo Dispositivo**
```
1. Usuário tem 5 favoritos e tema "light" na nuvem
2. Usuário faz login em novo dispositivo
3. Sistema detecta dados remotos
4. Dados são sincronizados para o dispositivo local
5. Usuário vê seus favoritos e tema imediatamente
```

### **Cenário 3: Conflito de Dados**
```
1. Usuário marca favorito no dispositivo A (offline)
2. Usuário marca favorito diferente no dispositivo B (online)
3. Sistema detecta conflito quando conectividade é restaurada
4. Conflito é resolvido automaticamente usando merge
5. Ambos os favoritos são preservados na nuvem
```

### **Cenário 4: Perda de Conectividade**
```
1. Usuário está usando o app normalmente
2. Conectividade é perdida
3. Sistema continua funcionando com dados locais
4. Quando conectividade é restaurada:
   - Dados locais são sincronizados com a nuvem
   - Dados da nuvem são sincronizados com o local
   - Conflitos são resolvidos automaticamente
```

## 🛠️ Como Usar

### **Para Desenvolvedores:**

#### **1. Injeção de Dependência**
```kotlin
@Inject
lateinit var favoritesRepository: FavoritesRepository

@Inject
lateinit var settingsRepository: SettingsRepository
```

#### **2. Sincronização Manual**
```kotlin
// Sincronizar quando necessário
val syncResult = favoritesRepository.syncWhenOnline()
if (syncResult is Result.Success) {
    // Sincronização bem-sucedida
} else {
    // Tratar erro
}
```

#### **3. Verificação de Conflitos**
```kotlin
// Verificar se há conflitos
if (favoritesRepository.checkForConflicts()) {
    // Resolver conflitos automaticamente
    val resolveResult = favoritesRepository.resolveConflicts()
}
```

### **Para Usuários Finais:**

#### **1. Login Automático**
- Usuário faz login normalmente
- Migração acontece automaticamente em background
- Dados são preservados e sincronizados

#### **2. Sincronização Automática**
- Sistema sincroniza automaticamente quando conectividade é restaurada
- Usuário não precisa fazer nada manualmente

#### **3. Resolução de Conflitos**
- Conflitos são resolvidos automaticamente
- Usuário não perde dados
